# Match3

**Тестовый Match3 проект** 

**Архитектурные решения и паттерны:**  
- **Bootstrapper** - единая точка входа для инициализации сервисов
- **GameStateMachine** - переключение состоянии проекта
- **LocatorService** - внедрение зависимостей
- **MVC** (model - класс BoardModel, отвечающий за хранение информации, 
          view - класс BoardView, отвечающий за отрисовку объектов, 
          controller - класс BoardController, отвечающий за обработку ввода и вычисления)
- **ObjectPool** - созданные объекты создаются 1 раз и переиспользуются

Использую загрузку через Resources, т.к для прототипирования этого достаточно. 
Не внедрял **Zenject** что бы использовать **ООП** по максимуму.
